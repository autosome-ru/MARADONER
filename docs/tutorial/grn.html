Gene regulatory network

Promoters against motifs

Motif activities tell what motifs are at work in a group of samples. The next question is what promoters each of them works on. The grn command tests each promoter against each motif in each group. Some people call the outcome a gene regulatory network (GRN), hence the name of the command. The method is a heuristic built on top of the fitted model.

> maradoner grn MyProject results

The command runs after predict. It writes a table of promoters by motifs for each group into the results/belief folder. A cell of a table is a belief: the posterior probability that the motif contributes to the expression of the promoter in that group.

There are as many tables as there are groups, and each one is comparable to the expression table in size. That is why they are stored in the HDF format by default.

How is a belief computed?

We take one promoter, one motif and one group. The model tells how much the motif contributes to the expression of the promoter in each sample of the group: it is the loading times the activity of the motif in the sample. With all the estimates plugged in, the expression of the promoter then has 2 explanations: the full model, and the same model with the contribution of the motif taken out.

Both explanations are Gaussian with the error variance of the group (times the weight of the promoter, if the model was fitted with --promoter-variance), so each has a likelihood. If $L_1$ is the likelihood of the full model, $L_0$ is the likelihood of the model without the motif and $π$ is the prior probability that a motif has an effect on a promoter, then the belief is $${π L_1}/{π L_1 + (1 - π) L_0}.$$ By default, $π$ is a neutral 0.5.

A belief above $π$ says that the promoter is explained better with the motif than without it, and a belief below $π$ says the opposite. A pair with a zero loading has a belief of $π$ exactly, as the motif contributes nothing to such a promoter either way. So with a sparse loading matrix only the promoters carrying a motif can be linked to it.

Nothing is fitted anew at this step. The estimates are plugged in as if they were exact, hence the word "heuristic" above.

From beliefs to a network

A table of beliefs is not a network yet. For each group, MARADONER also finds a threshold: the pairs with a belief at or above it have a Bayesian false discovery rate of 0.05. The threshold is a single number saved next to the table, e.g. results/belief/group_1.txt. The pairs passing it are the links of the network of the group:

In the picture, the darker a cell the higher the belief, and the outlined cells pass the threshold. Motif 3 and promoter 6 have no links at all. That is a regular outcome.

The synthetic loadings are dense (every motif has a non-zero loading at every promoter), so the network is dense too: a promoter is linked to 62 motifs and an active motif to 167 promoters (medians).

What about covariates?

In a project with covariates, an activity has one more part: the effect of a covariate times the covariate. By default it is tested in one lump with the mean and the deviation. With --no-means it is not tested at all, as it stays in both models. The --covariate option tests it alone. Let's take the project of the Covariates section and look for the promoters explained by the effect of age:

> maradoner grn MyProject results --covariate age

Here, the value of the option is the name of a covariate as create lists it. The second model of the picture above is now different: the motif keeps its mean and its deviations there and loses its effect of age. An effect is the same in all groups, so the samples are no longer split by groups. All of them enter one likelihood, each sample with the error variance of its group. The outcome is one table, results/belief/covariates/age.hdf, with a threshold next to it in age.txt.

The threshold is 0.87, and 66488 of the 840658 pairs (7.9%) pass it. All of them belong to motifs with a true effect of age. The stronger the effect the more promoters are linked to a motif: 31% of the pairs pass for the motifs with a true effect of 0.4 or more in absolute value, and none for those with an effect below 0.1. For the batch_batch_2 covariate, 1 pair of the 840658 passes. That's fine: the batches were assigned at random.

The option can be given several times for a table per covariate, and --covariate all stands for all the covariates of a project. The motifs removed by predict are absent from these tables as well, even though such a motif may have an effect of a covariate.

Reading the tables

A table is read in Python with pandas:

import pandas as pd

belief = pd.read_hdf('results/belief/group_1.hdf')
with open('results/belief/group_1.txt') as f:
    threshold = float(f.read())
pairs = belief.stack()
pairs = pairs[pairs >= threshold]

Here, pairs is a list of the promoter-motif pairs passing the threshold with their beliefs. The beliefs are stored in half precision to save space.

Options

Name Description Default value
--prior-h1 <float> The prior $π$: the expected fraction of motifs active at a promoter, strictly between 0 and 1 0.5
--no-means By default, the effect of a motif is its loading times its whole activity, the mean plus the deviation. With this option, only the deviation of the group is tested, and the mean activity stays in both models --means
--covariate <name> The effect of a covariate on the activities is tested in place of the activities, over all samples. The table goes to the belief/covariates folder. See above Disabled
--stat The likelihood ratios are saved alongside the beliefs, to the lr folder Disabled
--no-hdf Plain tab-separated tables in place of HDF --hdf

Promoters with an error variance of 0.001 or less are left out of the tables, and MARADONER prints a warning when that happens.
